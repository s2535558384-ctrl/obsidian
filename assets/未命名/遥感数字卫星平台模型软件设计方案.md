## 1 概述

### 1.1 编写目的

本文规定遥感数字卫星平台模型的软件总体架构与模块划分，明确整星模型框架、星上分系统、地面系统三大子系统的模块组成、模块职责与模块依赖关系，作为后续分系统详细设计、接口设计和研制实施的依据。

本稿聚焦模块划分。运行流程、时序、数据流、消息与数据结构详细定义、外部接口、性能与六性、测试与进度等内容后续展开。

### 1.2 适用范围

本方案覆盖：

- 整星模型框架：模型接入、组装、上下文、总线、调度、状态、快照及公共服务；
- 星上分系统：测控（A）、数传（B）、星间通信（C）、综合电子（D）、姿轨控（E）、供配电（F）、安全防护（G）、载荷（H）；
- 地面系统：运控中心终端、运控中心代理模型、地面测控站模型、地面数传站模型。

不包含：

- 卫星三维模型资源与三维渲染；
- 平行系统仿真引擎本身；
- 通信链路网络、感知图像生成、智能终端、蓝方目标等外部模型内部实现。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| 任务级 | 面向任务流程与关键状态的粗粒度模型，仿真级别编码 0 |
| 交战级 | 面向链路、几何、单机参数的细粒度模型，仿真级别编码 1 |
| 整星模型库 | 承载整星框架与 A~H 分系统、供引擎加载的动态库 |
| 地面模型库 | 承载运控中心代理模型与测控站/数传站模型的动态库 |
| 独立分系统模型库 | 仅承载一个分系统、可被引擎单独加载的动态库 |
| 逻辑总线 | 模型内部按消息字典与 recvID 寻址的强类型消息通道 |
| 实装帧 | 与真星接口控制文件一致的 1553B/SpaceWire/以太网数据帧 |
| 型号模板 | 一类卫星的分系统组成、参数、载荷清单与约束规则集合 |
| 想定 | 仿真引擎下发的实例初始化与运行参数 |
| 代理模型 | 引擎内代表运控中心终端的模型，只做协议转换与路由 |

### 1.4 参考文件

1. 《遥感数字卫星平台模型研制技术要求》（2026-09-01 版）；
2. 《项目群软件研制规范》；
3. 现有 ReconSatLib 代码框架及配置文件、接口头文件；
4. 各分系统实装接口控制文件（ICD，待提供）。

### 1.5 设计原则

1. **三大子系统解耦**：整星模型框架、星上分系统、地面系统分别设计、分别编译；跨子系统只通过公开接口或引擎端口交互。
2. **一套接口、两套实现**：每个星上分系统对外只暴露一个分系统框架（含统一接口与公共模板）；任务级、交战级各有一套算法模块，初始化与输入输出共享。
3. **逻辑总线 + 边界封解帧**：星内功能仿真使用强类型逻辑消息；与地面、半物理设备交界处统一封装解析实装帧。
4. **配置驱动**：卫星型号、分系统组成、参数与约束来自型号模板和想定，代码不写死型号差异。
5. **状态同构**：任务级与交战级每拍输出相同状态字段，级别切换不改变对外数据结构。
6. **模块单一职责**：模块只做本职，跨模块通过明确接口；公共能力下沉到公共服务模块，避免重复实现。
7. **国产化与自主可控**：C/C++ 开发，支持银河麒麟 V10 与鲲鹏 ARM；轨道/姿态算法属于自主可控实现。
8. **可独立测试**：每个星上分系统可编译为独立模型库；整星框架、星上分系统、地面系统均可单独测试。

## 2 系统组成

### 2.1 三大子系统

| 子系统 | 代号 | 职责 |
|---|---|---|
| 整星模型框架 | S1 | 承载并调度星上分系统，提供接入、组装、总线、时统、状态、快照与公共服务 |
| 星上分系统 | S2 | 实现 A~H 八个分系统的任务级/交战级业务算法与输入输出 |
| 地面系统 | S3 | 运控中心终端、代理模型、测控站模型、数传站模型 |

```text
遥感数字卫星平台模型
├─ S1 整星模型框架
│   ├─ 运行框架模块
│   └─ 公共服务模块
├─ S2 星上分系统
│   ├─ A 测控
│   ├─ B 数传
│   ├─ C 星间通信
│   ├─ D 综合电子
│   ├─ E 姿轨控
│   ├─ F 供配电
│   ├─ G 安全防护
│   └─ H 载荷
└─ S3 地面系统
    ├─ 运控中心终端
    ├─ 运控中心代理模型
    ├─ 测控站模型
    └─ 数传站模型
```

### 2.2 部署边界

| 部署单元 | 内容 | 运行形态 |
|---|---|---|
| 整星模型库 | S1 + S2 | 动态库，引擎按卫星实例加载 |
| 独立分系统模型库 | S1（裁剪为单分系统）+ 一个 S2 分系统 | 动态库，引擎单独加载 |
| 地面模型库 | S3 的代理模型与站模型 | 动态库，引擎按站实例加载 |
| 运控中心终端 | S3 的运控终端 | 独立进程，Qt Widgets/C++ |
| 外部模型/设备 | 通信链路网络、图像生成、智能终端、蓝方目标、半物理等 | 平行系统提供 |

### 2.3 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | 银河麒麟 V10 及其他符合国家标准的国产操作系统 |
| 处理器 | 鲲鹏等 ARM 架构处理器；x86 作为开发与功能验证环境 |
| 语言 | C++14（沿用现有 qmake 工程） |
| 构建 | qmake；第三方库按 `lib/<平台-架构>/` 目录约定组织 |
| 性能基线 | 以鲲鹏 ARM 单机为验收基线 |
| 部署 | 单机多实例；规模扩大时由引擎分布到多节点 |

### 2.4 对外接口清单

| 接口 | 方向 | 主要内容 | 承载方式 |
|---|---|---|---|
| 通信链路网络模型 | 双向 | 星间通信数据、前向/返向中继数据 | 引擎端口 |
| 感知图像生成模型 | 单向（模型 → 图像） | 卫星状态、载荷成像参数、成像工作指令 | 引擎端口 |
| 智能终端模型 | 双向 | 卫星状态/蓝方目标 ↔ 任务规划结果/终端状态 | 引擎端口 |
| 蓝方目标模型 | 单向（蓝方 → 模型） | 蓝方目标位置、地基武器状态 | 引擎端口 |
| 总线转网络设备 | 双向 | 1553B/SpaceWire/以太网帧封装的业务数据 | 半物理专网（TCP/UDP） |
| 半物理管控软件 | 单向（→ 模型） | 遥控指令/注入数据 | 半物理专网（TCP/UDP） |
| 综合业务智能管理软件 | 双向 | 模型/仿真状态 ↔ 初始化/导调命令 | 引擎端口 |

## 3 整星模型框架（S1）

### 3.1 模块总览

```text
S1 整星模型框架
├─ 3.2 运行框架模块
│   ├─ 模型接入模块
│   ├─ 模型组装模块
│   ├─ 仿真上下文模块
│   ├─ 总线路由模块
│   ├─ 时统与调度模块
│   ├─ 状态聚合模块
│   └─ 快照管理模块
└─ 3.3 公共服务模块
    ├─ 配置管理模块
    ├─ 消息字典模块
    ├─ 日志与事件模块
    └─ 帧编解码模块
```

运行框架模块负责“把模型跑起来”，公共服务模块负责“被运行框架和星上分系统共同使用”。公共服务模块以源码形式编入整星模型库、独立分系统模型库和地面模型库，不做独立动态库。

### 3.2 运行框架模块

#### 3.2.1 模型接入模块

| 项 | 内容 |
|---|---|
| 职责 | 实现 `IModel`/`EngineAdapter`；提供整星、独立分系统两种模型壳；处理初始化、步进、导调、快照、停止入口；把想定 JSON 交给组装模块；把状态、日志、事件交给引擎 |
| 关键内容 | `init`、`runStep`、`inputData`、`saveSnapshot`、`loadSnapshot`、`stop`；输出 `satInformation`、`satTaskStatus`；日志与事件适配 |
| 不负责 | 业务算法、配置规则、消息路由、状态计算 |
| 依赖 | 模型组装、仿真上下文、状态聚合、日志与事件 |

#### 3.2.2 模型组装模块

| 项 | 内容 |
|---|---|
| 职责 | 按型号模板创建、初始化、销毁分系统组件；维护本星分系统清单；管理模型生命周期状态 |
| 关键内容 | 分系统工厂、组装清单、初始化顺序、失败回滚、独立模型库的单分系统组装 |
| 不负责 | 分系统内部初始化内容、参数校验规则、运行期调度 |
| 依赖 | 配置管理、星上分系统框架 |

#### 3.2.3 仿真上下文模块

| 项 | 内容 |
|---|---|
| 职责 | 保存本星唯一运行期上下文：卫星标识、型号模板、仿真级别、仿真时间、步长、运行状态 |
| 关键内容 | `satId`、`satName`、`satType`、`simLevel`、`simTime`、`step`、`runState`、模板版本 |
| 不负责 | 时间推进、状态聚合、配置解析 |
| 依赖 | 无（纯数据对象，由其他模块读写） |

#### 3.2.4 总线路由模块

| 项 | 内容 |
|---|---|
| 职责 | 按 `recvID` 和订阅表投递强类型消息；处理广播；维护待投递队列；以订阅表作为共享访问控制 |
| 关键内容 | 订阅表、地址门、广播标记、待投递队列、消息计数、溢出与丢弃策略 |
| 不负责 | 消息结构定义（消息字典）、业务处理、实装帧编解码 |
| 依赖 | 消息字典、星上分系统输入输出模块 |

#### 3.2.5 时统与调度模块

| 项 | 内容 |
|---|---|
| 职责 | 把引擎时间换算为 UTC/MJD；管理步长、跳时、暂停、结束；按固定顺序调用分系统框架 |
| 关键内容 | 时间换算、调度表、固定调用顺序、每拍阶段划分、跳时处理 |
| 不负责 | 业务算法、状态输出、配置解析 |
| 依赖 | 仿真上下文、星上分系统框架 |

#### 3.2.6 状态聚合模块

| 项 | 内容 |
|---|---|
| 职责 | 每拍拉取各星上分系统的状态段，按固定槽位写入整星聚合状态；校验字段完整性；独立模型库时只输出本分系统段 |
| 关键内容 | `SatSimStatusData` 组装、槽位映射、未初始化检查、聚合同构校验 |
| 不负责 | 状态计算（分系统负责）、序列化（接入模块负责） |
| 依赖 | 星上分系统状态导出接口、公开状态结构 |

#### 3.2.7 快照管理模块

| 项 | 内容 |
|---|---|
| 职责 | 保存/恢复仿真上下文、调度器状态、总线待投递队列、各分系统状态结构；校验快照版本与型号模板 |
| 关键内容 | 快照头、版本策略、分段遍历、定长队列镜像、恢复顺序 |
| 不负责 | 动态容器序列化（分系统负责镜像到定长结构）、快照文件存储（引擎负责） |
| 依赖 | 仿真上下文、星上分系统状态结构 |

### 3.3 公共服务模块

#### 3.3.1 配置管理模块

| 项 | 内容 |

## 4 星上分系统（S2）

### 4.1 S2 组成

S2 分为“公共部分”和“算法部分”：

```text
S2 星上分系统
├─ S2 公共部分
│   ├─ 分系统框架
│   ├─ 初始化模块
│   └─ 输入输出模块
└─ S2 算法部分
    ├─ A 测控
    ├─ B 数传
    ├─ C 星间通信
    ├─ D 综合电子
    ├─ E 姿轨控
    ├─ F 供配电
    ├─ G 安全防护
    └─ H 载荷
```

- **S2 公共部分**：每个分系统都有，但只在 4.2 节写一次，定义统一接口、生命周期、级别切换，以及配置、消息、遥测、状态、故障、能耗、要素的通用处理；
- **S2 算法部分**：按分系统展开，只写任务级/交战级算法模块，不重复公共部分；
- 每个分系统 = S2 公共部分（三个模块）+ 任务级算法模块 + 交战级算法模块；
- 公共模块在各分系统之间的差异（配置参数、遥测表、消息字段、状态结构、故障码、能耗参数）不在本方案体现，放到详细设计文档。

### 4.2 S2 公共部分

#### 4.2.1 分系统框架

| 项 | 内容 |
|---|---|
| 职责 | 对整星框架暴露统一接口；创建并持有初始化、输入输出、两级算法；管理生命周期；执行级别切换；导出状态段；提供状态、遥测、故障、能耗、任务/工作特性要素的统一实现与码表 |
| 关键接口 | 生命周期、消息输入、参数设置、故障设置、状态导出、遥测采集、事件/日志采集、级别切换 |
| 不负责 | 具体算法、配置解析、消息路由 |
| 依赖 | 初始化模块、输入输出模块、任务级算法、交战级算法、公开状态/遥测/故障/能耗结构 |

内部分项：

| 子项 | 内容 |
|---|---|
| 框架接口 | 统一组件接口、生命周期、级别切换、状态导出 |
| 状态模板 | 状态结构初始化、字段刷新、状态段导出 |
| 遥测模板 | 遥测参数表、采样周期、编码、采集 |
| 故障模板 | 统一故障类型/级别/影响范围码表、健康状态、功能降级钩子 |
| 能耗模板 | 实时功耗计算、累计耗电量、交战级曲线采样 |
| 要素模板 | 任务特性/工作特性要素的状态标志与输出 |

约定：

- 故障编码 `faultFlag = (类型 << 8) | 级别`，级别 1=一般、2=严重；
- 故障注入统一经 D 转发，分系统框架的故障模板提供降级钩子；
- 任务级上报分系统总功耗，交战级可细化到单机；
- 状态结构为定长 POD，两级算法共用。

### 4.3 S2 算法部分

每个分系统只写职责、任务级算法模块、交战级算法模块和与其他分系统的关系；公共部分见 4.2 节，不重复。

#### 4.3.1 A 测控

**职责与组成**：星地遥测/遥控、测控链路、GNSS 数据、测控任务与故障；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 遥测组帧：按遥测参数表构造星地遥测数据帧；
- 遥控解析转发：接收地面遥控帧，解析后转发综合电子；
- 测控任务控制：测控任务开始/停止、故障状态设置。

**交战级算法模块**

- 链路预算：可见性、链路匹配性、空间损耗、信道余量、链路可用性；
- 天线指向：按地面站位置与卫星实时位置计算天线指向；
- GNSS 数据生成：按卫星实时位置生成 GNSS 数据送综合电子；
- 交战级帧处理：高/中/低轨遥测/遥控帧的构造与解析。

**与其他分系统的关系**：与 D 交换遥控/遥测；与地面测控站经引擎交互；调用 E 提供的可见性公共函数；使用帧编解码模块。

#### 4.3.2 B 数传

**职责与组成**：星地数传、中继数传、星上固存与数传链路；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 星地/中继传输时间计算：按数传模式、速率和数据量计算传输时间；
- 数传任务控制：星地/中继数传任务开始、停止、故障设置。

**交战级算法模块**

- 星地/中继链路：链路建立、维持、可用性；
- 天线指向与转动：星地/中继天线实时指向与转动参数；
- 固存管理：存储读写、余量、数据平衡状态；
- 链路预算：速率、误码率、余量、可用性。

**与其他分系统的关系**：从 H 获取数传数据；与地面数传站/中继经引擎交互；调用 E 提供的可见性公共函数；使用帧编解码模块。

#### 4.3.3 C 星间通信

**职责与组成**：星间链路、路由、数据收发；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 星间传输时间计算：按频段、速率和数据量计算任务持续时间；
- 通信任务控制：星间通信任务开始、停止、故障设置。

**交战级算法模块**

- 星间链路建立/维持：天线指向、链路可用性、链路持续状态；
- 路由：按星间路由参数选择对端与转发路径；
- 数据收发：收发状态、传输时间、剩余数据量；
- 天线指向与链路预算。

**与其他分系统的关系**：与通信链路网络模型经引擎交互；获取对端卫星位置；调用 E 提供的可见性公共函数；使用帧编解码模块。

#### 4.3.4 D 综合电子

**职责与组成**：遥控解析分发、遥测采集、星上任务规划、任务/延时队列、总线管理；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 遥控解析分发：解析星上遥控数据，按目标分系统构造控制命令；
- 遥测采集：按遥测参数表采集各分系统遥测；
- 故障转发：把外部故障设置命令转发到目标分系统；
- 工作模式管理：整星工作模式设置与切换。

**交战级算法模块**

- 任务规划：按目标库、可见窗口、姿态机动、能源/存储约束做启发式规划；
- 任务队列/延时队列：队列管理、时序约束、执行控制；
- 总线管理：总线类型、带宽、消息调度；
- 遥测组包：按星上帧格式、包格式、帧周期、逻辑时序组包；
- 规划时延模拟：规划算法与队列操作的运行时延。

**与其他分系统的关系**：所有分系统的指令与遥测汇聚点；与智能终端模型交互任务列表；接收外部故障设置；与 A 交换遥控/遥测。

#### 4.3.5 E 姿轨控

**职责与组成**：轨道外推、姿态控制、轨道控制、太阳翼/天线机构、地影与太阳；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 轨道外推：按初始根数与历元实时外推轨道；
- 坐标转换：J2000、WGS-84/地固系、站心系等坐标转换；
- 太阳/地影：太阳位置、进出影状态与预报；
- 可见性公共函数（对外）：无状态几何可见性计算，供 A/B/C/G 与地面调用。

**交战级算法模块**

- 姿态控制：姿态机动、稳定、模式指向；
- 轨道控制：控制量计算、推力器工作参数、开关机、推进剂；
- 太阳翼/天线机构：太阳翼指向与转动、数传/中继/星间天线转动参数；
- 姿态稳定度、太阳入射角。

**与其他分系统的关系**：向 A/B/C/F/G/H 提供轨道、姿态、太阳、地影状态；对外提供可见性公共函数；不调用可见性函数本身。

#### 4.3.6 F 供配电

**职责与组成**：能源汇总、蓄电池充放电、能源平衡与告警；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 负载汇总：汇总各分系统能耗；
- 放电深度、充电计算、能源平衡。

**交战级算法模块**

- 母线电压/电流；
- 充放电曲线；
- 能源工作模式（充电、放电、分流、最小能源）；
- 欠压预警与载荷能源安全告警。

**与其他分系统的关系**：接收各分系统能耗上报；向 D/H/G 提供能源状态与告警。

#### 4.3.7 G 安全防护

**职责与组成**：抵近威胁告警、激光/射频告警、主动规避、帆板调整；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 抵近威胁告警：按蓝方在轨卫星位置计算告警；
- 激光/射频告警：按蓝方地基武器状态计算告警；
- 主动规避任务控制：规避任务开始、停止。

**交战级算法模块**

- 轨道机动参数：按规避命令计算轨道机动控制参数；
- 帆板调整参数：按帆板姿态调整命令计算控制参数；
- 告警细化：告警类型、级别、影响范围。

**与其他分系统的关系**：接收蓝方目标模型数据；向 D/E 输出告警与规避参数；调用 E 提供的可见性公共函数。

#### 4.3.8 H 载荷

**职责与组成**：载荷开关机、工作模式、成像参数、数据率；由 S2 公共部分 + 两级算法组成。

**任务级算法模块**

- 开关机/模式管理；
- 功耗；
- 侦察任务启停。

**交战级算法模块**

- 光学/SAR/雷达/电侦模式参数；
- 成像参数；
- 覆盖参数；
- 数据率/数据量。

**与其他分系统的关系**：接收 D 的任务与模式指令；向 B 提供数传数据；向感知图像生成模型提供成像参数与平台状态；覆盖范围由图像生成模型计算，H 保留覆盖结果回传/转发接口。

### 4.4 分系统章节编写约定

总体设计方案中，每个分系统章节只写职责与算法模块，不写公共模块的差异：

S2 公共部分（分系统框架、初始化模块、输入输出模块）只在 4.2 节描述，不在各分系统章节重复；公共模块在各分系统之间的差异不在本方案体现，放到详细设计文档。

2. **公共服务模块不依赖运行框架模块**，避免反向耦合；
3. **星上分系统之间不直接调用**，跨分系统交互一律走逻辑总线；
4. **星上分系统不依赖地面系统**，地面系统也不依赖星上分系统的内部模块；
5. **地面系统与整星框架只经引擎端口交互**；终端与代理模型只经 TCP 交互；
6. **公共服务源码可被多个目标编译**，但不形成动态库依赖；
7. **禁止循环依赖**：S1 运行框架 → S2 分系统框架 → S1 公共服务；公共服务不得反向依赖运行框架或分系统；
8. **可见性函数是 E 算法模块对外提供的无状态纯函数**：调用方只传几何输入，不访问 E 的运行状态或业务逻辑，不视为跨分系统业务调用。
